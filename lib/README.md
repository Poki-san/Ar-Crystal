# Структура приложения ECHO WEAR

Код организован по принципу **feature-first**: каждая пользовательская
возможность находится в собственном модуле. Внутри сложного модуля применяются
слои из ТЗ.

```text
lib/
├── core/                    # Общая тема и инфраструктура без бизнес-логики
├── features/
│   ├── scanner/             # Камера, звук и анализ исходной текстуры
│   │   ├── data/            # Работа с камерой, файлами и аудио
│   │   ├── domain/entities/ # Результат и этапы сканирования
│   │   └── presentation/    # Экран сценария «Создать»
│   ├── crystallizer/        # Модель одежды и общий генератор принта
│   │   ├── domain/entities/ # Независимые данные предмета
│   │   └── presentation/    # Рендерер и виджет превью
│   ├── ar_preview/          # Камера, распознавание позы и AR-наложение
│   ├── gallery/             # Локальная коллекция и её хранилище
│   ├── item/                # Карточка созданного предмета
│   ├── market/              # Офлайн-демонстрация маркетплейса
│   ├── profile/             # Профиль пользователя
│   └── shell/               # Нижняя навигация приложения
├── app.dart                 # MaterialApp и глобальная конфигурация
└── main.dart                # Точка входа
```

## Направление зависимостей

- `presentation` использует сущности `domain` и вызывает сервисы `data`;
- `data` возвращает типы из `domain`, не содержит виджетов;
- модуль AR использует результат `crystallizer`, но не знает, как он был снят;
- `core` содержит только действительно общие части приложения;
- сетевой и blockchain-слои отсутствуют намеренно: текущая версия работает
  локально и не включает бэкенд согласно ограничениям проекта.

## Правила для новых файлов

1. Экран отвечает за пользовательский сценарий, а не за алгоритмы обработки.
2. Повторяемая отрисовка выносится в `widgets` или `rendering`.
3. Данные между слоями передаются через именованные сущности из `domain`.
4. Комментарий объясняет причину решения; очевидные строки кода не комментируются.
5. Новый общий класс помещается в `core` только если его используют несколько
   независимых модулей и в нём нет предметной логики ECHO WEAR.
